# Fablewood

**From an AI-generated 3D character to a playable third-person game in Unity, built by a complete beginner with AI help.**

Fablewood is the companion project for a YouTube tutorial: https://www.youtube.com/watch?v=40vP0HBejs0

It takes a character named **Finn** through the whole pipeline:

1. Generate the 3D model with AI (**Hyper3D Rodin** or **Tripo**).
2. Rig it automatically in **AccuRig**.
3. Import it into **Unity 6** as a Humanoid.
4. Wire it up with a **one-click character controller setup tool**.
5. Run around Unity's **Fantasy Kingdom** demo village.

Everything in `Assets/Fablewood` was written by AI from a single prompt, which is included as [`Assets/character_controller_instructions.txt`](Assets/character_controller_instructions.txt).

### What's *not* in this repository (and why)

The project uses two **free** Unity Asset Store packs. Their licenses don't allow them to be re-uploaded to GitHub, and Fantasy Kingdom alone is over 1 GB. You add them yourself in a few clicks (see [Setup](#setup)):

- **[Human Basic Motions FREE](https://assetstore.unity.com/packages/3d/animations/basic-motions-free-154271)** by Kevin Iglesias: idle, walk, run and jump animations.
- **[Fantasy Kingdom in Unity 6 | URP](https://assetstore.unity.com/packages/slug/298128)** by Unity Technologies: the village environment.

> **Why aren't these in `Packages/manifest.json`?** The manifest can only list Unity *Package Manager* packages, such as URP, Input System and Cinemachine. Those are listed there and download automatically. Asset Store packs can't be added to the manifest, so the project opens a **Required Assets** window when they're missing, with links to both.

## Setup

### 1. Get the project
Either:
- **Clone it:** `git clone https://github.com/mdj128/FableWood.git`, or
- **Download it:** on GitHub click **Code → Download ZIP**, then unzip it.

### 2. Open it in Unity
1. Open **Unity Hub** and go to **Projects → Add → Add project from disk**.
2. Select the `FableWood` folder.
3. If the Hub asks you to install Unity **6000.3.10f1**, install it.
4. Open the project. The first open takes a few minutes while Unity downloads its packages.

You may see some warnings or pink materials at first. That's expected until the two packs below are imported. A **Fablewood - Required Assets** window also opens and lists what's missing. You can reopen it any time from **Tools → Fablewood → Required Assets**.

### 3. Import the free Asset Store packs
For each pack:
1. Click **Open in Asset Store** in the Required Assets window, or use the links above. Sign in and click **Add to My Assets**. Both packs are free.
2. In Unity, open **Window → Package Manager**.
3. In the left sidebar choose **My Assets**, select the pack, and click **Download**, then **Import**.

Import the packs in this order:

1. **Human Basic Motions FREE**: import everything.
2. **Fantasy Kingdom in Unity 6 | URP**: it's large, so give it time.
   - Unity will warn that the pack **overwrites Project Settings**. Click **Import**. Fantasy Kingdom needs its own quality and lighting settings, and this repository already uses the same ones.
   - Collision for all the buildings, floors and stairs is added automatically during the import.

When both are done, everything links back up by itself. The Required Assets window shows two green checkmarks.

### 4. Try it out
Open **`Assets/Scenes/SampleScene.unity`** and press **Play**.

| Control | Keyboard and mouse | Gamepad |
|---|---|---|
| Move | **W A S D** or arrow keys | Left stick |
| Look around | **Mouse** | Right stick |
| Sprint | Hold **Left Shift** | Click left stick |
| Jump | **Space** | A (South button) |
| Zoom camera | **Scroll wheel** | |
| Free the mouse cursor | **Esc** (click the Game view to lock it again) | |

## The full walkthrough: make your own character

This is the pipeline from the video. Finn was made this way, and you can make your own character the same way.

### Step 1: Generate a 3D character with AI

Use **[Hyper3D Rodin](https://hyper3d.ai/)** or **[Tripo](https://www.tripo3d.ai/)**. Both can turn a text prompt or an image into a textured 3D model.

Tips for a model that rigs well:
- Ask for a **full-body** character standing in a **T-pose or A-pose**, with arms held away from the body and legs slightly apart.
- Use a **neutral pose and expression**: no props in the hands, nothing covering the hands or feet.
- Avoid very long capes, robes or tails for your first try, because they're harder to rig.
- Example prompt: *"Stylized fantasy adventurer boy, full body, standing in A-pose, arms away from body, simple clothing, game-ready character"*
- If you start from an image, use a clean front view of the whole character on a plain background.

Download the model as **FBX** if you can; GLB or OBJ also works for the next step. Include the textures.

> Tripo has its own auto-rigging option, but for this project we use AccuRig, which gives a clean Humanoid skeleton that Unity understands.

### Step 2: Rig it in AccuRig

**[AccuRig](https://actorcore.reallusion.com/auto-rig)** is a free auto-rigger from Reallusion.

1. Open AccuRig and click **Import Model**. Choose your FBX or OBJ.
2. **Rig Body:** follow the on-screen guide to place the markers on the chin, wrists, elbows, knees and groin. Click **Rig Body**.
3. **Rig Hands:** check the finger markers and click **Rig Hand**. Choose the right number of fingers if your character isn't five-fingered.
4. Preview a few motions in the viewer to check that the arms and legs bend properly. Adjust the markers and re-rig if something looks wrong.
5. Click **Export → Export FBX**:
   - **Target:** Unity
   - **Embed textures:** on
   - Export just the **character in its T/A-pose**, without an animation.

You now have a rigged FBX, like `Finn_Rigged.fbx`.

### Step 3: Import the character into Unity

1. Open this project in Unity (see [Setup](#setup)).
2. In the **Project** window, open the `Assets/Character` folder.
3. Drag your rigged FBX from your computer's file browser into that folder.

### Step 4: Set the rig to Humanoid

1. Click your FBX in the Project window.
2. In the **Inspector**, open the **Rig** tab.
3. Set **Animation Type** to **Humanoid**.
4. Leave **Avatar Definition** on **Create From This Model** and click **Apply**.
5. Optional check: click **Configure…**. Every body bone should be green. Click **Done** to return.

If the textures are missing, open the **Materials** tab and click **Extract Textures…**, then choose a folder such as `Assets/Character`.

Humanoid is what lets the Kevin Iglesias animations, made for a different character, play on yours.

### Step 5: Wire up the character controller (one click)

1. Drag your character from the Project window into the **Scene**.
2. Make sure there's ground under it. The setup window offers a **Create Ground Plane** button if there isn't.
3. Select the character in the **Hierarchy**.
4. Open **Tools → Fablewood → Setup Character Controller**.
5. Review the **animation clips** it found for Idle, Walk, Run, Jump, Fall and Land. They're picked automatically from the Kevin Iglesias pack.
   - Use the **Suggestions** dropdowns or drag in any clip to change them.
   - Switch **Prefer clips for** between Male and Female to use the other animation set.
6. Click **Setup**.

The tool then:
- Checks the character has a Humanoid avatar and finds its Animator.
- Adds a **CharacterController** sized to the character, with its feet on the ground.
- Adds the **ThirdPersonController** script.
- Sets up a **ThirdPersonCamera** on the Main Camera, or creates a camera if there isn't one.
- Builds an **Animator Controller** in `Assets/Fablewood/Animations` with:
  - a blend tree for idle, walk and run
  - Jump, Fall and Land states
  - root motion turned off
- Assigns the controller to your character.

Running Setup again updates the existing setup instead of adding duplicates, and changes to the scene support **Ctrl+Z**.

7. **Save the scene** with Ctrl+S, then press **Play**.

### Step 6: Explore the Fantasy Kingdom demo scene

1. Open the demo with **Fantasy Kingdom → Load Demo Scenes** from the top menu, or double-click `Assets/Scenes/Demo.unity`.
2. Drag your character into the scene and place it on a street. Use the Scene view and the Move tool, and make sure its feet are on or slightly above the ground, not under it.
3. **Turn off the demo's own cameras.** They have their own camera controllers that fight with ours.
   - In the Hierarchy search box, type `Camera`.
   - Select **MainCamera** and **Physical Camera** (and any other camera object it finds) and untick the checkbox next to their names in the Inspector.
4. Select your character and run **Tools → Fablewood → Setup Character Controller → Setup**. With the demo cameras off, it creates a new Main Camera that follows your character.
5. **Turn on post-processing** for the new camera, or the Game view will look much brighter than the Scene view:
   - Select **Main Camera**.
   - In the Camera component, under **Rendering**, tick **Post Processing**.
6. Optional: **hide the "Quality Level" box** in the top-right corner. In the Hierarchy, search `Quality` and untick **QualitySettingsButton** and **QualitySettingsController**. The controller also switches quality levels on a key press, which changes the lighting.
7. Save the scene and press **Play**. Collision for the buildings, floors and stairs is already in place.

## How it works (and how to customize it)

### Character movement: `ThirdPersonController`
Select your character to change these in the Inspector. Every setting has a tooltip.

- **Movement:**
  - **Walk Speed** / **Sprint Speed** (meters per second)
  - **Acceleration** / **Deceleration**
  - **Rotation Smooth Time** (lower turns faster)
- **Jumping & Gravity:**
  - **Jump Height** (meters)
  - **Gravity**
  - **Coyote Time**: a short grace period for jumping just after walking off a ledge
- **Ground Detection:** which layers count as ground.

The character walks the way it's **facing** and slows down during sharp turns, so it turns on the spot instead of sliding sideways. All movement is done in code, so root motion is off.

> If you change Walk Speed or Sprint Speed, run **Setup** again so the animation blend tree matches the new speeds.

### Camera: `ThirdPersonCamera`
Select the Main Camera to adjust:
- **Target** and **Target Offset**: who to follow and how high to aim.
- **Distance**, plus the minimum and maximum zoom distance.
- **Mouse Sensitivity** and **Invert Y**.
- **Pitch limits**: how far the camera can look up and down.
- **Avoid Obstacles**: whether the camera moves in front of walls.

### Animation
The generated Animator Controller uses three parameters, all set by the movement script:
- **Speed**: the character's actual speed in m/s. It drives the Idle → Walk → Run blend tree.
- **IsGrounded**: whether the character is on the ground.
- **Jump**: a trigger, set when Space is pressed.

The setup tool prefers **in-place** animation clips, not the `[RM]` root-motion versions, because the script moves the character.

## Troubleshooting

| Problem | Fix |
|---|---|
| Pink or missing materials, missing scripts | One or both Asset Store packs aren't imported yet. See **Tools → Fablewood → Required Assets**. |
| The character slides around without animating | Import **Human Basic Motions FREE**, then run **Setup** again. |
| "Does not have a valid Humanoid avatar" | Select the FBX, set **Rig → Animation Type → Humanoid** and click **Apply**. |
| The character floats or sinks a little | Run **Setup** again. It resizes the CharacterController to fit the character. |
| Falls through the ground at Play | There's no collider under it. Add a ground plane (the setup window has a button) or place the character above the terrain or floor. |
| Falls through Fantasy Kingdom stairs or floors | Right-click `Assets/Art/Meshes/Compositions` and choose **Reimport** to regenerate their colliders. |
| Gets stuck at the bottom of stairs | The steps are taller than the CharacterController's **Step Offset**. Raise it a little, or put an invisible ramp over the stairs: a Cube with its Mesh Renderer turned off. |
| The camera doesn't follow | The camera needs the **Third Person Camera** component with your character as **Target**, and it shouldn't have other camera scripts on it. Running **Setup** again fixes this. |
| The Game view is much brighter than the Scene view | Tick **Post Processing** on the camera, under Camera → Rendering. |
| The mouse cursor disappeared | Press **Esc**. Click the Game view to lock it again. |
